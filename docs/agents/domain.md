# Domain docs

## Before exploring

This repo uses a single-context layout.

Read root `GLOSSARY.md` and the ADRs in `docs/adr/` relevant to the work.

If a domain document is absent, proceed silently. The domain-modeling
skill creates documents when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
Respect the glossary's avoided synonyms.

If a needed concept is missing, reconsider the terminology or note the
gap for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, identifying the ADR
and explaining why the decision should be reopened.
